PRIORITY 1 — CORE PRODUCT

4. Booking workflow

Currently parents can effectively book tutors directly.

I want to investigate changing the workflow to:

Parent requests session
→ pending_tutor_response

Tutor can:
A. Accept
→ awaiting_payment
→ payment
→ scheduled

B. Suggest alternative date/time
→ alternative_proposed
→ parent accepts or declines
→ if accepted, awaiting_payment

C. Decline
→ declined

Analyse:

* required database/status changes
* API changes
* tutor UI
* parent UI
* notifications
* payment timing
* interaction with existing availability system

Do not implement until the architecture is proposed.

* date-specific unavailable periods
* ability to block a whole date or date range
